# Aion Agent 战略复盘与建议文档

> 状态：建议稿（2026-08-07），待后续逐步实施。
> 本文档沉淀「内部体检」结论与外部视角补充，供后续决策参考。

## 一、现状定位
- 形态：自包含 Android App，内嵌 Python 引擎 + 本地服务，BYOK + 数据本地存储。
- 本质：**应用层去中心化**（数据在端侧、零后端），**推理层仍中心化**（依赖云端 LLM）。

## 二、认知架构自检结论（内部体检）
1. 潜意识注入：成立——稳定画像高频注入，省去每轮「你是谁 / 我们在干嘛」的重载成本。
2. 主动回忆：成立——低频高价值认知（如项目愿景）放 recall 层，高频画像放注入层，分层自洽。
3. 五维认知 + 双层记忆：成立——state 维度必须带过期时间；env 维度是快照、不进皮层。
> 注：以上为运行体验总结，多为定性结论，缺少可测量指标，价值有限。

## 三、三条裂缝（最值得带走的部分）
1. **认知绑定在实现上**：记忆格式未标准化前，「数据归用户」只是换了个托管方（从平台换成我们的实现）。
2. **记忆是单 agent 的**：缺多设备同步、跨 agent 认证、迁移协议——「载体标准 > 应用」。
3. **隐私叙事在推理层不成立**：BYOK 会把上下文发给云端；梦境模式批量处理认知数据风险最高。

## 四、外部视角修正
- 「数据归用户」运动已有失败样本（Solid / ActivityPub / IndieWeb / Nextcloud）：
  协议没有嵌入用户已在用的产品，就没有流量；没有流量就没有生态；没有生态就没有标准。
- 协议不是写出来的，是被生态逼出来的：优先兼容已有协议（MCP），
  先成为「最好用的记忆实现」，再谈格式成为事实标准。
- 北极星修正：平台 → 协议 → **「开放实现 + 生态」**。
  格式是承诺，实现是信任，生态才是壁垒。

## 五、建议优先级
1. 【最先】开放记忆格式：版本化导出/导入规范 + `/api/memory/export` + 示例 schema。
2. 【最急】推理层隐私：梦境模式默认关闭 / 本地模型选项 / 批量敏感处理需用户确认。
3. 【最不急】跨 agent 互操作：有第二个使用者后再做认证与同步协议。
4. 【长期】MCP 化：把记忆层暴露为 MCP server，让任何 agent 可读写。

## 六、商业定位备忘
- 记忆内容 = 产品；记忆格式 = 承诺；实现 = 信任；生态 = 护城河。
- 协议本身不赚钱，围绕协议的实现 / 迁移工具 / 同步托管 / 企业版才赚钱（Linux 式定位）。
- 出路：垂直场景（学习 / 陪伴 / 教育）小规模验证 → 开源社区 → SDK / MCP 基础设施。

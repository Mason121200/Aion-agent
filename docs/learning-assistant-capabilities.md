# 学习助手能力模型（设计对齐 v0.1）

> 定位：全方位辅助用户学习、全场景覆盖、实时跟进、确保学完。
> 方法论：「有教无类」= 覆盖所有学习者与场景；「因材施教」= 基于画像个性化教学。
> 本文档回答：要成为这样的学习助手，需要哪些功能与知识，以及工程上如何落地。

## 1. 一句话架构

```
认识用户（画像层）
  ↓ 决定
教学策略（因材施教层）  ← 需要学习科学与教学法知识
  ↓ 驱动
闭环执行（学习管理引擎）  方案→执行→验收→复习→分析→调整→完成
  ↓ 展开
全场景覆盖（场景矩阵）
  ↑ 贯穿
实时跟进与主动干预（进度/提醒/防放弃）
```

## 2. 六层能力拆解

### A. 认识用户（画像层）——因材施教的前提
功能：
- 学习者画像库：静态属性（目标/职业/学历）+ 动态行为画像（持续更新，不靠一次性问卷）
- 学习风格推断：视觉/听觉/读写/动觉（VARK），从行为特征推断（爱看图表还是听讲解、爱提问还是自查）
- 专注模式：最佳学习时段、单次专注时长（从学习记录统计）
- 知识基线：已掌握/薄弱知识点（与知识图谱对齐）
- 动机档案：内在/外在动机、坚持动力来源

知识：VARK 学习风格、认知负荷理论、艾宾浩斯遗忘曲线、布鲁姆认知分类（了解→理解→应用→分析→评价→创造）。

### B. 教学内容层（知识底座）
功能：
- 知识图谱：学科知识点、依赖关系、难度（如：微积分依赖代数基础）
- 内容库：教材/讲解/资料，按知识点挂载（RAG 检索基础）
- 评估题库：自测题、随堂测验、测验自动生成
- 错题本：错题归因（概念不清/粗心/没见过），按知识点聚类

知识：每个学科自身的知识结构（领域建模）；出题学（测验设计）。

### C. 教学策略层（因材施教的核心）
功能：
- 策略选择器：按画像 + 当前状态选教学方式（讲解/案例/练习/项目/探究）
- 难度调节：最近发展区（ZPD）——难度略高于当前水平，动态升降
- 方式切换：视觉型给图、听觉型给讲解、动觉型给实操
- 脚手架：新知识给支架，熟练后撤除
- 学习科学调度：主动回忆、间隔重复、交错练习、生成效应（让用户自己产出）
- 费曼输出引导：学完要求用户讲出来，暴露理解缺口

知识：间隔重复、主动回忆、交错练习、生成效应（学习科学四大基石）；维果茨基最近发展区；支架式教学；自我决定理论（自主/胜任/联结）。

### D. 闭环执行引擎（学习管理）
承接上一版「学习闭环设计」：需求明确 → 个性化方案（内容+节奏+策略+复习计划）→ 每日任务派发 → 检视验收（证据+掌握度）→ 复习调度 → 数据分析 → 动态调整 → 完成判定 → 沉淀认知。
关键升级：**方案不是模板，是按画像定制**（节奏、策略、难度、复习频率都因人而异）。

### E. 全场景覆盖（场景矩阵）
按「学习前 / 学习中 / 学习后」×「场景类型」展开：
- 学习前：目标设定、起点测评、资料搜集、预习、计划
- 学习中：讲解、答疑、练习、实操、笔记、专注（番茄钟）、口语/写作练习
- 学习后：复习、测验、错题整理、总结、费曼输出
- 场景类型：备考（考试目标）、语言学习、编程/技能、通识阅读、课堂跟课、碎片问答
- 形态：对话、文档、提醒、进度看板、语音（后续）

### F. 实时跟进与主动干预（确保学完）
功能：
- 进度看板：任务/计划/复习的实时状态
- 主动提醒：学习提醒、复习提醒、逾期提醒
- 异常检测：连续 N 天无记录、进度停滞、掌握度下滑 → 主动询问并干预
- 卡点救援：用户说「不会/学不动」时诊断原因 → 换策略/降难度/换教法
- 激励防放弃：正反馈、里程碑庆祝、目标回顾（唤醒动机）
- 健康守护：番茄钟休息提醒、疲劳检测
- 阶段复盘：数据回顾 + 下阶段建议

知识：习惯养成（最小行动/习惯循环）、拖延心理、动机维持。

## 3. 工程落地映射（对照 aion_agent 现状）

| 能力 | 落点 | 现状 |
|------|------|------|
| 画像 | 认知层扩展 profile 数据（或独立 profile.json + Triple） | 无 |
| 知识图谱 | 认知库（Triple + Note + 向量检索）已有基础 | 半有 |
| 内容库 | study 资料 + RAG 检索 | 有框架，无内容 |
| 评估题库 | 新 eval 模块（测验记录/掌握度/正确率） | 无 |
| 错题本 | 新 mistake 模块（知识点归因） | 无 |
| 策略选择 | 提示词 + 规则（LLM 按画像选教法） | 无 |
| 复习引擎 | study_repo 扩展 review_items（间隔调度） | 无 |
| 提醒 | 现有 reminder + watcher 模式扩展 | 有，可扩展 |
| 番茄钟/专注 | 新工具（start_focus/log） | 无 |
| 停滞检测 | 后台 watcher（现有 reminder watcher 模式） | 无 |
| 看板 | 现有 UI 扩展 | 部分 |
| 沉淀 | 认知写入（已有）+ 学习总结 | 部分 |

结论：通用底座（认知层/工具/技能/循环/持久化）已就绪，学习助手 = 一个不断生长的技能生态 + 画像数据层 + 教学策略提示词库 + 评估/复习引擎。

## 4. 分阶段落地（建议）

- **P0（先跑通闭环，当前可做）**：最小画像（目标/时长/时段/风格粗分，从对话与行为推断）→ 个性化方案（含复习计划）→ 评估（自测打分+掌握度）→ 复习调度 → 停滞检测与主动提醒 → 完成判定
- **P1（做厚因材施教）**：错题本、知识点关联、策略选择器（LLM 自动换教法）、番茄钟、测验生成
- **P2（全场景）**：语音交互、课堂跟课、多计划并行、深度归因报告、学习数据导出

## 5. 待讨论决策点

1. **画像来源**：从对话与行为自动推断（推荐，零负担）vs 学习前问卷？
2. **知识图谱先做哪个学科**：语言 / 编程 / 备考通用框架？
3. **评估方式**：AI 生成测验自测（客观数据）vs 用户自报掌握度（轻量）？
4. **干预程度**：提醒与询问（温和）vs 强制打断（激进）？
5. **本轮范围**：先 P0 闭环，还是先把画像 + 策略做厚再动闭环？

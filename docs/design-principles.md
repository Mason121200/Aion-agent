# Aion Agent 设计准则（开发铁律）

> 生效范围：所有功能、工具、规则层代码。
> 两条基础理念：① 任何功能都服务于优化 agent 的自我学习进程，且不破坏 LLM 自主决策；
> ② 任何功能都服务于用户，且不破坏 LLM 的自我学习进程。

## 三条判据（新功能上线前必过）

任何功能/工具/规则在落地前，逐条回答：

1. **它提升 agent 的自我学习进程吗？**
   （沉淀、检索、验证、调整、迁移。如果既不帮助 agent 学得更好，也不服务用户——砍掉。）

2. **决策权在 LLM 吗？**
   规则层只允许做三件事：**度量**（计算指标）、**执行**（落实 LLM 已做的决定）、**报告**（产出数据）。
   规则层禁止：代替 LLM 判定「有效/无效」「完成/未完成」、代替 LLM 沉淀/回滚。
   凡是涉及「该不该」「行不行」「对不对」的裁决，必须由 LLM 通过工具显式做出。

3. **它服务用户，且不污染学习进程吗？**
   用户数据 → 学习输入（单向）；学习结论 → 用户服务（单向）。
   禁止把用户侧的一次性噪音回灌成 agent 的长期认知；禁止规则层绕过 LLM 直接改写画像/记忆。

## 头脑与手脚的分工

| 角色 | 允许做什么 | 禁止做什么 |
|------|-----------|-----------|
| **LLM（大脑）** | 决策、判断、取舍、教学、裁决 | 无（权限由安全层约束） |
| **规则层（手脚）** | 度量指标、执行工具、生成报告、防呆拦截 | 裁决有效/无效、判定完成、自动沉淀画像/记忆 |
| **数据层（仓库）** | 读写、去重、持久化 | 产生任何业务结论 |

## 已落地的裁决点（示例）

- 调整实验：规则层到期只生成前后对比报告（`pending_review`），LLM 调用
  `confirm_adjustment` 裁决采纳/不采纳；采纳才沉淀为有效学习方法。
- 完成判定：规则层出 `completion_check` 验收报告，LLM 调用
  `confirm_plan_completion` 做出完成裁决。
- 学习画像：由 LLM 通过 `profile_collect` 主动收集，规则层只落库。

## 禁止清单（反面教材）

- ❌ 后台定时器直接判定调整「有效/无效」并沉淀画像
- ❌ 规则层自动把计划置为 completed
- ❌ 工具执行成功就自动写入长期认知（必须由 LLM 表达沉淀意图）

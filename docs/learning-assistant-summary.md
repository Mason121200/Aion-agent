# 学习助手设计对齐·总结（决策记录 v0.2）

> 本文件是学习助手设计讨论的汇总索引与决策记录（v0.2 已拍板 1-5）。
> 配套文档：`study-loop-design.md`（管理闭环）、`learning-assistant-capabilities.md`（能力模型）、`teaching-flow.md`（教学流程）。

## 1. 目标

「有教无类、因材施教」的学习助手：全场景覆盖、实时跟进、确保学完。
因材施教的最终形态：**系统通过调整实验，自己找到最适合用户的学习方法**。

## 2. 完整闭环（8 环节）

需求明确 → 方案制定 → 执行 → 检视验收 → 复习 → 数据分析 → 动态调整 → 完成判定 → 归档沉淀

## 3. 完整教学流程（4 层）

- 宏观（学科级 8 步）：摸底画像 → 目标设定 → 个性化方案 → 阶段教学 → 阶段验收 → 数据分析 → 动态调整 → 完成判定
- 中观（单元级 8 步）：导学 → 讲授（按画像选方式）→ 理解确认 → 练习（脚手架→独立）→ 反馈纠正 → 测验 → 错题 → 复习调度
- 微观（会话级 6 步）：回顾 → 微目标 → 学习（番茄钟）→ 输出（费曼）→ 记录 → 衔接
- 贯穿（决策矩阵）：风格→呈现方式；测验数据→难度；异常→干预；进度+遗忘曲线→复习间隔

## 4. 已有 vs 待建

已有（底座，直接复用）：对话讲授/答疑、认知记忆层、工具系统、技能系统、计划/进度、学习记录、提醒、资料库、RAG、会话持久化、MCP、同步。

有雏形需加深：数据分析（仅 pace）、完成判定（手动）、总结沉淀（部分）、进度看板（基础）。

待建（六大模块）：学习者画像、评估引擎、错题本、复习调度、数据分析、主动干预。另有：知识图谱、策略选择器、番茄钟（P1/P2）。

## 5. 架构决策（双轨架构）

学习数据层（结构化台账，新建）→ 提炼管道（规则统计 + LLM 归纳）→ 认知层（已有，复用）→ 注入教学决策。

原则：
- 画像拆两类：语义事实 → 认知层；派生指标 → 现算不存
- 事件台账 ≠ 认知：台账留结构化层，提炼成结论才进认知层
- 认知层=大脑，数据层=病历，提炼管道=分析师

## 6. 已拍板决策（v0.2）

1. **复习粒度**：材料级/进度级为主，同时知识点与错题自动记录并入下次复习队列
2. **验收方式**：不靠用户自评——里程碑完成 + 用户测试数据打分；可按实际情况调整
3. **复习算法**：按学习进度 + 遗忘曲线动态调度（不是固定间隔，不是纯 SM-2）
4. **动态调整**：调整范围涵盖全部（方案/教学方式/复习方式/验收标准等）；系统自主调整（含全自动完成判定，见 5）；每次调整必须记录数据，对比调整前后学习效果，以寻找最适合用户的方法
5. **完成判定**：全自动（规则 + 数据驱动，无需用户确认）

## 7. 调整实验机制（第 4 点展开，核心新设计）

目的：找到最适合用户的学习方法（因材施教的收敛机制）。

流程（每个调整 = 一次实验）：
1. **基线快照**：调整前记录近期效果指标——进度速度、测验正确率、复习完成率、学习频率
2. **调整记录**：记录调整内容（改了方案/教法/复习/验收的什么）、调整时间、原因（来自分析）
3. **观察窗口**：调整后持续观察（默认一个阶段或 7 天，可配置）
4. **效果对比**：窗口结束后对比「调整后 vs 基线」各指标
5. **结论沉淀**：
   - 有效（指标提升）→ 保留调整，沉淀为「该用户的有效方法」写入画像（认知层，带 confidence）
   - 无效（持平/下降）→ 回滚或再调整，记录失败经验
6. **方法库收敛**：多轮实验后，画像中积累「对用户有效的教学组合」（教法+节奏+复习+验收），后续方案直接引用

数据模型：`plans[].adjustments[]`（ts/内容/原因/基线快照/观察窗口/效果对比/结论）。

## 8.6 主动参与机制（P0.5，2026-08-08 实现并真实验证）

目标：agent 不是被动记录员，而是主动的教学者与数据采集者——用户补录是兜底，agent 主动收集是主渠道。

实现：
- `prompts.py` 新增 `STUDY_TOOL_HINT`：主动教学（讲解+出题+测验验收）、主动采集（自动 log_study_session / test_log / mistake_add，细节主动追问）、主动复习（list_reviews 到期项逐项提问并 review_checkin）、主动分析与调整
- `react_chat_session.py` 动态上下文注入：到期复习项 / 学习停滞 / 进行中计划 / 提醒（修复 datetime 未导入导致注入静默失败的问题）
- 真实对话验证：用户只说「背了单词半小时」→ 自动 log_study_session + 主动检查复习队列 + 引用调整过的学习方法；「听力题错了好几道」→ 自动 mistake_add（详细归因）+ 主动讲解同义替换套路
- 测试：`tests/test_study_proactive.py` 3 个（提示词注入 + 到期复习注入 + 停滞注入），全量 293 passed

## 9. P0 实现清单（基于已拍板决策）

**数据层（study.json 扩展）**
- `plans[].acceptance`：验收标准（与里程碑/测验挂钩，不靠自评）
- `plans[].checkins[]`：结构化检视（摘要/测验引用/进度）
- `plans[].tests[]` 或独立 tests：测验记录（题目/分数/知识点/时间）
- `plans[].mistakes[]`：错题（内容/归因/关联知识点/复习状态）
- `plans[].review_items[]`：复习项（来源=材料/知识点/错题；next_review_at；interval 按进度+遗忘曲线；连续正确）
- `plans[].adjustments[]`：调整实验（基线/观察窗口/对比/结论）
- `plans[].completion`：完成报告（全自动判定生成）
- `analysis_logs`：分析历史

**引擎**
- 评估引擎：测验打分（规则计算正确率/掌握度），验收 = 里程碑完成 + 测验数据
- 复习调度器：进度 + 遗忘曲线（掌握度 → 间隔；生疏短间隔，熟练拉长）
- 提炼管道：规则统计 → LLM 归纳 → 认知沉淀（薄弱点/有效方法）
- 调整实验器：基线快照 → 观察 → 对比报告 → LLM 裁决（采纳沉淀/不采纳留痕）
- 完成判定器：规则层出验收报告 → LLM 完成裁决（completed + 报告）
- 停滞检测 + 主动提醒（复用 reminder watcher 模式）

**工具（skill 扩展）**
- study skill 新增：`test_log`（记录测验）、`mistake_add`（记录错题）、`review_checkin`（复习打卡）、`plan_adjust`（调整实验入口）、`plan_completion_check` + `confirm_plan_completion`（完成验收报告 + LLM 裁决）`confirm_adjustment`（调整裁决）
- 现有工具改造：plan_create 增加 acceptance/review_strategy；plan_checkin 改为引用测验数据而非自评

**验证**：电脑端跑通「建计划（带验收）→ 学 → 测验 → 错题 → 复习 → 停滞提醒 → 调整实验（报告→LLM 裁决）→ 完成验收（报告→LLM 裁决）」全链路，测试覆盖后再打包。
